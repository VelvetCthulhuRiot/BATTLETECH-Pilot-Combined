> 我不是律师，下面不是法律意见；但每一件"需要你自己拍板"的事都点明了。

## 2. 游戏 IP

* **BATTLETECH**、**MechWarrior** 是各自权利人的商标。本 MOD **不含**游戏素材，需要正版游戏，
  与 Harebrained Schemes / Paradox Interactive **无隶属或背书关系**（README 里已声明）。
* MOD 采用"运行时挂钩"而不是"替换游戏文件"：不修改任何原文件，删除即恢复原状。
  这在 MOD 社区是最常见、也最不容易惹麻烦的做法。
* 画像里**不要**刻意生成与游戏内有名角色高度相似的形象（例如照着 Glitch / Behemoth 的脸去生成）。
  风格相近（机甲驾驶员、神经头盔）本身没问题，**具体角色的可识别形象**才有风险。

## 3. AI 生成图片的版权：分三层看

### 第一层：模型许可（**最需要你确认的一层**）

**生成物的许可跟随"模型"的许可，而不是跟随工具（ComfyUI）。** 请按你实际用的 checkpoint 对照：

| 模型家族 | 典型许可 | 商用 | 备注 |
|---|---|---|---|
| Stable Diffusion 1.5 系 | CreativeML Open RAIL-M | 允许，**带使用限制** | 限制写在附件 A（不得用于违法、伤害、虚假信息等），不禁止发布图像 |
| SDXL / SD 2.x | CreativeML Open RAIL++-M 等 | 允许，带使用限制 | 同上 |
| **FLUX.1 [dev]** | FLUX.1 dev 非商用许可 | **禁止商用** | 免费 MOD 一般属非商用，但**再分发**也要看条款 |
| FLUX.1 [schnell] | Apache-2.0 | 允许 | |
| 社区微调（Pony / Illustrious / 各类 merge） | **各自自定** | **逐个看** | 有的明确写"禁止商用"或"不得再分发输出" |
| LoRA / embedding / ControlNet 权重 | **各自自定** | **逐个看** | 常被忽略：LoRA 也可能带"禁商用/禁再分发" |

**如果你的 checkpoint 或 LoRA 里有"禁止再分发输出"的条款**，就把图片从仓库里移除
（见第 5 节：仓库不带图也能正常工作）。

### 第二层：各国法律对"AI 生成物"的态度

* **美国**：版权局（USCO）立场是"纯 AI 生成、缺乏人类作者身份的内容**不受版权保护**"。
  这看着像坏消息，但对发布者其实偏宽松 —— 既然没有可主张的版权，也就**没有第三方版权可供你侵犯**
  （前提是没有复制他人受保护的作品）。
* **中国**：北京互联网法院 2023 年"AI 生成图片著作权案"承认**有独创性投入**的 AI 图片可构成作品。
  也就是说你付出提示词/构图/筛选/后期投入的部分，可能受保护。
* **欧盟 / 英国等**：各有差异（英国对"计算机生成作品"有专门规定）。
* 实务结论：**只要你没有用他人图片做 img2img、没有提示真人姓名或受保护角色、且模型许可允许，
  发布这些图的风险很低。** 但"低风险"不等于"零风险"，最终由你拍板。

### 第三层：你是不是"抄了别人的图"

三种要避开的情况：

1. **img2img / ControlNet 用了别人的照片或画作当底图** ⇒ 源图的权利会带进来；
2. **提示词里写了真人姓名**（演员/网红）⇒ 可能涉及肖像权、公开权；
3. **提示词指向具体受版权保护的角色**（某动画/游戏角色的可识别形象）⇒ 角色形象本身可能受保护。

本仓库的 75 张图是"通用驾驶员肖像"风格、无人名提示，属于风险最低的一类。

## 4. 建议保留的"生成凭据"

为了让上面的问题以后能被回答（也为了你自己复查），建议：

* **保留 PNG 里的 ComfyUI 元数据**（提示词、模型名、seed 等会自动写进 PNG 的 tEXt 块）。
  它是"这是我自己生成的"最直接的凭据。若担心隐私（元数据里可能含本机路径），
  可以用脚本只清掉路径字段、保留模型名与 seed。
* 或在本文档里补一张表：**每批图 → 用的 checkpoint / LoRA 名称与版本 → 各自的许可结论**。
  下面是个可以直接填的模板：

```
批次          数量    checkpoint / 版本              LoRA               许可结论
female 01-59   59     <例如 sd_xl_base_1.0>          <无 / 名称>         <允许发布 / 需确认>
male 01-12     12     ...
other 01-04     4     ...
```

* 抠图脚本如果是你自己写的，那部分处理不足以产生新的权利，但也不引入新的权利问题。

## 5. 想 100% 稳妥？那就"只发 MOD、不带图"

本 MOD **设计上就不依赖具体图片**：

* 一张图都没有时，头像替换功能会**自动关闭**（并在 `combined.json` 里写回 `enabled: false`），
  此时 MOD 只剩"性别比例调节"，完全可用；
* 用户把自己的图丢进 `portraits\female|male|other\` 就能启用替换（`portraits\README.txt` 有完整说明）。

所以有两个发布方案，随你选：

| 方案 | 仓库内容 | 优点 | 缺点 |
|---|---|---|---|
| **A. 带图发布** | 代码 + 配置 + 75 张图（当前状态，23 MB） | 开箱即用 | 需要先核对模型/LoRA 许可（第 3 节第一层） |
| **B. 只发本体** | 代码 + 配置 + 空 `portraits\`；图片单独放进 Release 附件，或干脆让用户自备 | 许可上最干净，仓库也小 | 用户要自己准备图 |

两者对代码与功能没有任何区别 —— 换方案只是"挪不挪那 75 个 PNG"。

## 6. 结论（一句话版）

* **代码**：你自己的，MIT 发布没问题 ✅
* **游戏素材**：一个都没有，无需担心 ✅
* **AI 头像**：**是否可发布取决于你用的 checkpoint 与 LoRA 的许可**（重点核对 FLUX.1 dev 这类非商用模型、
  以及标注"禁止再分发产出"的 LoRA）；法律层面（美/中）对"无人类独创性投入的纯 AI 产出"通常不产生
  第三方版权障碍，但各地不同。
* **拿不准时**：用第 5 节的**方案 B**（仓库不带图）—— 功能完全不受影响，也不会有人认为你占了什么便宜。
