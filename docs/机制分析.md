# BATTLETECH 驾驶员头像机制 —— 反编译级分析

分析目标：**BATTLETECH 1.9.1，Build 686R，BuildStamp 200226-live-cdbbe62**（Steam 版，最终版本）。
反编译对象：`BattleTech_Data\Managed\Assembly-CSharp.dll`（Mono/.NET，未做混淆）。
本文所有结论都来自对 IL 的实际阅读，不是猜测。

---

## 1. 三套数据结构

### 1.1 `PilotDef`（驾驶员定义）

`data/pilot/pilot_*.json` 反序列化的目标类型，命名空间 `BattleTech`，public。

```
BattleTech.PilotDef
  get_Description()            -> HumanDescriptionDef   (Id / Name / Callsign / Icon ...)
  get_PortraitSettings()       -> BattleTech.Portraits.PortraitSettings
  set_PortraitSettings(value)
  GetPortraitSprite(DataManager dataManager)      -> UnityEngine.Sprite
  GetPortraitSpriteThumb(DataManager dataManager) -> UnityEngine.Sprite
  field portraitSettings              // 运行时对象，不直接来自 JSON
  field portraitSettingsID            // 序列化用
  field portraitSettingsJson          // 序列化用
  field cachedSprite / cachedSpriteThumb / cachedSpriteCombat
```

**关键点：`portraitSettings` 不出现在 pilot JSON 里**，它是运行时被塞进去的（见 §3）。
JSON 里唯一与头像有关的字段是 `Description.Icon`。

内置示例：

| JSON | `Description.Icon` | 含义 |
|---|---|---|
| `pilot_ronin_Apex.json` | `Apex` | mwportraits AssetBundle 里的固定位图 |
| `pilot_fp_BW_NatashaKerensky.json` | `guiTxrPort_GenericMW_default_utr` | StreamingAssets 里的松散 PNG |
| `pilot_sim_starter_dekker.json` | `guiTxrPort_Dekker_holder_utr` | 同上（`_holder_` 是占位图命名习惯） |
| `pilot_vehicle_noncom.json` | `""`（空） | 没有位图，只能靠渲染 |

### 1.2 固定位图 = `Sprite` 类型的资源

`BattleTech_Data\StreamingAssets\data\VersionManifest.csv`（10820 行）的格式：

```
id,type,path,version,addedOn,updatedOn,removedOn,assetBundleName,assetBundlePersistent,assetBundleCRC,<IsTemplate>,addendum
```

头像相关的两类条目：

```
guiTxrPort_backerAlaniz_utr,Sprite,sprites/Portraits/guiTxrPort_backerAlaniz_utr.png,171,...,,,,False,0,False,False
Apex,Sprite,Assets/UI/MWPortraits/Apex.png,171,...,,mwportraits,True,2272080716,False,False
```

* `assetBundleName` 为空 → **松散文件**，实际路径 `StreamingAssets/sprites/Portraits/*.png`（共 176 个）
* `assetBundleName = mwportraits` → 打进 `data/assetbundles/mwportraits`（Apex、Wildfire、Kamea、Sumo… 约 20 个）

`BattleTech\StreamingAssets\data\genderedoptions\genderedoptionslistdef_mechwarriorPortraits.json`
按性别列出可用的 MWPortrait 名字（Female: Apex/Arclight/Buckshot/Gargoyle/Mockingbird/Overload/Showboat/Wildfire；
Male: Bullhorn/Bulwark/Kraken/Myrmidon/Ozone/Paradise/Sumo/Witness）。
`PilotGenerator..ctor` 里只做了 `GenderedOptionsListDefs.Get(constants.Pilot.PilotPortraits)` 后丢弃返回值（预加载惯用法），
**不参与随机驾驶员头像的分配**。

**精灵加载路径**（`SpriteLoadRequest.Load()` IL）：

```
1. ResourceLocator.EntryByID(resourceId, 66 /*Texture2D*/, false) 命中
       -> TextureManager（走 file:// 或 Resources）
2. manifestEntry.IsAssetBundled == true
       -> AssetBundleManager
3. manifestEntry.IsResourcesAsset == true   // path.StartsWith("Assets/Resources")
       -> Resources.Load
4. 否则
       -> SpriteFromDisk(manifestEntry.FilePath)
```

`SpriteLoadRequest.SpriteFromDisk(assetPath)` 的实际行为：

```csharp
if (!File.Exists(assetPath)) return null;
byte[] data = File.ReadAllBytes(assetPath);
Texture2D tex = TextureManager.IsDDS(data) ? TextureManager.LoadTextureDXT(data)
              : new Texture2D(2, 2, TextureFormat.RGBA32, false);
if (TextureManager.IsPNG(data) || TextureManager.IsJPG(data)) tex.LoadImage(data);
else { LogWarning("Unable to load unknown file type from disk (not DDS, PNG, or JPG) at: {0}"); return null; }
return Sprite.Create(tex, new Rect(0,0,tex.width,tex.height), new Vector2(0.5f,0.5f), 100f, 0, 0);
```

`VersionManifestEntry`：

```csharp
get_FileName()  => Path.GetFileName(CurrentPath)
get_FilePath()  => Path.Combine(Application.streamingAssetsPath, CurrentPath)   // ← 见 §5
get_IsResourcesAsset() => path.StartsWith("Assets/Resources")
get_IsAssetBundled()   => !string.IsNullOrEmpty(assetBundleName)
```

`TextureManager.GetPath(resourceId)`：

```csharp
var entry = resourceLocator.EntryByID(resourceId, 66 /*Texture2D*/, false);
if (entry == null) { LogError("Could not find Texture2D Manifest entry for Id: " + resourceId); return ""; }
if (loadingMethod is 1 or 2) return entry.FilePath;
return string.Format("{0}://{1}", "file", entry.FilePath);
```

**数据侧**：`data/portraits/` 下 331 个 `PortraitSettings` 类型条目，
`PortraitPreset_1..326` 是脸谱预设，另有 `PortraitPreset_behemoth/dekker/glitch/medusa`。
一个预设长这样（`PortraitPreset_1.json`）：

```json

  "lightRig": 2, "cameraPosition": 1, "complexionTex": 3, "eyebrowTex": 2,
  "tattooTex": 1, "actualTattooTex": 3, "weights": [ ... 6 个混合权重 ... ],
  "browOffsetY": -0.007, "noseBridgeScale": -0.132, "noseTipScale": 0.109,
  "chinScale": 0.2662281, "cheekOffsetY": 0.00387, "eyeWidth": 0.0042, "jawWidth": 0.066,

  "hairTipId": "Hair_08", "tattooColorId": "Tattoo_04", "lipColorId": "Lip_01" }
```

**渲染侧**：`BattleTech.Portraits.PortraitManager`（public，场景里的单例 MonoBehaviour）。

```
fields: portraitCam, _post, portraitRenderer, suit, hair, facialHair, hairtex,
        complexionAlbedos, complexionSmoothness, complexionNormals, eyebrowMasks,
        tattooMasks, faceStubble, brow, noseBridge, noseTip, chinTip, cheek,
        eyeScalar, jawScalar, lightRigs, scarSets, tattooSets, headAnimation,
        cameraPositions, renderResults, renderRequests, defaultRenderTextures ...

portraitSizes 是嵌套枚举 PortraitManager.PortraitSizes { VERYSMALL, SMALL, MEDIUM, LARGE }

public void GeneratePortraitTexture(
        PortraitSettings settings,
        Action<RenderedPortraitResult> loaded,
        Action<string> failed,
        PortraitManager.PortraitSizes[] sizes)

private void RequestRenderPortrait(settings, size, target, success, failure)
private IEnumerator RenderRoutine(...)
private void ActualRender(...)
```

`PortraitManager` 自身实现了 `IDictionary<string, RenderedPortraitResult>`，索引器公开：

```csharp
public RenderedPortraitResult get_Item(string key) => renderResults[key];
public void set_Item(string key, RenderedPortraitResult value) => renderResults[key] = value;
```

**字典的键是 `settings.Description.Id`（字符串）**，不是 `PortraitSettings` 对象本身 —— 见
`GeneratePortraitTexture` IL：`renderResults.TryGetValue(settings.get_Description().get_Id(), out local)`
以及 `PortraitSettings.IsRendered(sizes)`：`PortraitManager.ContainsKey(Description.Id)`。

**结果类型**（字段签名 `06 15 12 80d502 11 c00078e4 12 808d` 解码结果）：

```csharp
public class RenderedPortraitResult {
    private Dictionary<PortraitManager.PortraitSizes, UnityEngine.Texture2D> results;  // ← Texture2D，不是 Sprite！
    public Texture2D this[PortraitManager.PortraitSizes size] { get; set; }
    public void ClearSize(size); public bool ContainsSize(size); public bool ContainsSizes(sizes);
}
```

确认方式：`PortraitRenderPanel.portraitPreviewImage` 是 `UnityEngine.UI.RawImage`，
`<smallPortrait>` 字段类型是 `UnityEngine.Texture2D`，而 `<Render>b__16_0` 里
`portraitPreviewImage.set_texture(result[512])`、`set_smallPortrait(result[128])`。

`GeneratePortraitTexture` 的核心逻辑：

```csharp
settings.LoadColorSwatchesById();
RenderedPortraitResult r;
if (renderResults.TryGetValue(settings.Description.Id, out r) && r.ContainsSizes(sizes)) {
    loaded?.Invoke(r);            // 已有缓存
    return;
}
// 否则建 RenderPortraitRequest，塞进 renderRequests 队列，交给 Update() 里的协程渲染
```

`PortraitSettings.RenderPortrait(DataManager dataManager, Action callback, PortraitSizes[] sizes)`：

```csharp
if (sizes == null || sizes.Length == 0) sizes = new[] { PortraitSizes.VERYSMALL, PortraitSizes.MEDIUM };
if (IsRendered(sizes)) { callback?.Invoke(); return; }        // 命中缓存，回调是无参 Action
if (loading) { loadComplete = (Action)Delegate.Combine(loadComplete, callback); return; }
loading = true;
loadComplete = (Action)Delegate.Combine(loadComplete, callback);
dataManager.PortraitManager.GeneratePortraitTexture(this, <RenderPortrait>b__99_0, <RenderPortrait>b__99_1, sizes);
```

`<RenderPortrait>b__99_0(result)` 只做三件事：`loadComplete?.Invoke(); loadComplete = null; loading = false;`
**它并不把 result 写进字典**（写字典发生在渲染协程里）。
⇒ 消费者拿到的其实是"无参回调"通知，然后自己去 `manager[settingsId][size]` 取图。
⇒ 所以任何自己接管 `GeneratePortraitTexture` 的实现，**必须顺手把结果写进 `manager[settingsId]`**。

## 2. UI 怎么决定用哪一套

以 `BattleTech.UI.TaskManagementElement.UpdateTaskInfo`（医疗舱任务条）为例：

```csharp
if (pilot.pilotDef.PortraitSettings != null) {
    SetIcon("uixTxrIcon_atlas");
    pilot.pilotDef.PortraitSettings.RenderPortrait(
        sim.DataManager,
        new Action(<UpdateTaskInfo>b__30_3),
        new[] { PortraitSizes.SMALL /*64*/ });
} else {
    SetIcon(pilot.GetPortraitSpriteThumb());
}
```

同样的二元分支出现在：

* `BattleTech.UI.SGBarracksRosterList`（兵营名册，`<WaitForPortraitRender>d__47`）
* `BattleTech.UI.PortraitRenderPanel.Render` → `PortraitManager.GeneratePortraitTexture(settings, b__16_0, b__16_1, {128, 512})`
* `BattleTech.UI.SGCharacterCreationNameAndAppearanceScreen`（有 `portraitRenderPanel` 字段）
* `BattleTech.UI.Tooltips.TooltipPrefab_Mechwarrior`（`<WaitForPortrait>d__20`）
* `BattleTech.UI.SGMemorialWallWidget`（阵亡墙）
* `BattleTech.UI.LanceMechPilotPortraits` / `CombatHUDPortrait`

`Pilot.GetPortraitSprite()` / `GetPortraitSpriteThumb()` 只是转发：

```csharp
public Sprite GetPortraitSprite()      => pilotDef.GetPortraitSprite(pilotDef.DataManager);
public Sprite GetPortraitSpriteThumb() => pilotDef.GetPortraitSpriteThumb(pilotDef.DataManager);
```

`PilotDef.GetPortraitSpriteThumb(dataManager)` 的有效逻辑（IL 末尾）：

```csharp
if (cachedSpriteThumb == null && DependenciesLoaded(...)) {
    cachedSpriteThumb = DownsampleSprite(dataManager.SpriteCache.GetSprite(Description.Icon));
}
return cachedSpriteThumb;
```

注意 `SpriteCache.GetSprite(id)` **只查缓存不加载**，真正的加载请求来自
`PilotDef.GatherDependencies(loadRequest)`：

```csharp

    loadRequest.RequestResource(44 /*PortraitSettings*/, PortraitSettings.Description.Id);
else if (!string.IsNullOrEmpty(Description.Icon))
    loadRequest.RequestResource(61 /*Sprite*/, Description.Icon);
```

以及 `PilotDef.DependenciesLoaded(...)`：

```csharp
if (dataManager == null) return false;
if (!string.IsNullOrEmpty(Description.Icon)
    && !dataManager.Exists(61 /*Sprite*/, Description.Icon)
    && PortraitSettings == null) { cachedSprite = null; return false; }
... 检查 ability ...
```

## 3. 随机驾驶员为什么会拿到 `PortraitSettings`

`BattleTech.PilotGenerator.GenerateRandomPilot(difficulty, ...)` 的收尾部分：

```csharp
HumanDescriptionDef desc = new HumanDescriptionDef(callsign, first, last, gender, factionID, age, details, null);
PilotDef def = new PilotDef(desc, ..., spentXP, ...);
def.set_DataManager(sim.DataManager);                                   // ← 先设 DataManager
def.set_PortraitSettings(GetPortraitForGenderAndAge(gender, age, discard));  // ← 再塞脸谱
def.ForceRefreshAbilityDefs();
sim.pilotGenCallsignDiscardPile.Add(def.Description.Callsign);
return def;
```

`GetPortraitForGenderAndAge(gender, age, discardPile)`：

```csharp
var entries = dataManager.ResourceLocator.AllEntriesOfResource(44 /*PortraitSettings*/, false);
List<PortraitSettings> all = ...;                       // 逐个 dataManager.PortraitSettings.Get(entry.Id)
var matched = all.FindAll(ps => ps.MatchesAge(age) && ps.get_Gender() == gender);
if (matched.Count == 0) LogWarning("Cannot find any portrait settings to match Gender {0} and Age {1}");
// 用 sim.pilotGenPortraitDiscardPile 做「弃牌堆」，尽量避免重复；牌堆快见底时重置
return matched[rand.Next(matched.Count)];
```

结论：

* **随机生成的雇佣兵一定会带 `PortraitSettings`** → 走 3D 渲染路线 → 改 `Description.Icon` 对他没用
* `SimGameState.GetUnusedRonin()` 有剩余时优先招传奇佣兵（带固定位图）→ 这就是"传奇佣兵头像固定"的来源
* `PortraitSettings.BecomeCustom()` / `IsCustom()` / `PortraitManager.GetNextUniqueCustomPortraitID()` /
  `CustomPortrait_1_2_ID_{0}` 说明玩家在"整容弹窗"里改过的脸会变成带唯一 ID 的自定义 settings
* 玩家指挥官同样带 `PortraitSettings`

## 4. 钩子选择与理由

| 钩子 | 作用 | 为什么选它 |
|---|---|---|
| `PortraitManager.GeneratePortraitTexture` **Prefix** | 所有 3D 形态头像的唯一收口 | 名册 / 医疗舱 / Skirmish / 角色创建预览 / 整容弹窗预览 / 阵亡墙 / tooltip 全部经过它。改这一处 = 全覆盖，且 3D 管线完全不启动 |
| `PilotDef.GetPortraitSprite` / `GetPortraitSpriteThumb` **Postfix** | 固定位图形态的驾驶员 | UI 的 `else` 分支调它们；Postfix 换返回值最干净 |
| `PilotDef.get_PortraitSettings` **Postfix（只读）** | 建立 `settingsId → PilotDef` 关联 | 让"呼号 / 标签"规则对 3D 形态驾驶员也生效。**不改返回值**，零副作用 |
| `SGCharacterCreationNameAndAppearanceScreen.OnAddedToHierarchy` **Postfix** | 可选：`SetActive(false)` 隐藏「自定义外貌」按钮 | 用 `AccessTools.TypeByName` + 反射取字段，避免编译期依赖 UI 内部类型 |

**被否掉的方案：把 `PilotDef.get_PortraitSettings()` 前缀改成返回 `null`。**
UI 会因此自动退回 Sprite 路线，看起来更省事，但下列调用点**不加判空**直接使用返回值：

* `BattleTech.UI.SGBarracksMWCustomizationPopup.IsDirty`（`callvirt get_PortraitSettings` 后立刻 `PortraitSettings.Equals(...)`）
* `BattleTech.UI.SGBarracksMWCustomizationPopup.LoadPilot`
* `BattleTech.UI.SGCharacterCreationWidget.<GoToPortraitCustomization>b__12_0`
* `BattleTech.UI.SGCharacterCreationSummaryScreen.Summarize`

一改就可能空引用崩溃，尤其"兵营整容弹窗"正是玩家常开的地方。所以最终选了"只拦渲染结果"。

## 5. ModLoader 机制（顺便解释了纯数据路线的可能性）

`BattleTech.ModSupport.ModLoader`（在 `Assembly-CSharp.dll` 里，不在独立 DLL 中）。

### 5.1 清单条目如何变成资源

```csharp
VANILLA_TYPES = Enum.GetNames(typeof(BattleTechResourceType));   // ← 包含 "Sprite"、"Texture2D"、"SVGAsset" ...
MODTEK_TYPES  = { "Video", "AdvancedJSONMerge", "GameTip", "SoundBank", "DebugSettings" };

ExpandManifest(gameModDef):
    // 路径 = Path.Combine(modDef.Directory, entry.Path) 然后 GetFullPath()  → 绝对路径
    // 若是目录 -> GetFiles(dir, "*", AllDirectories) 逐个展开
    // Id = entry.Id ?? InferIDFromFile(path)   // = Path.GetFileNameWithoutExtension
    //      或 JSON 里的 Description.Id / id / Id / ID / identifier / Identifier
    // Type 必须属于 VANILLA_TYPES ∪ MODTEK_TYPES ∪ 自定义类型

AddModEntry(entry):
    if 自定义类型 -> CustomResources[type][id] = entry
    else          -> AddBTRLEntries.Add(entry)      // 日志里写作 "Add/Replace"
```

`AddBTRLEntries` 在 `FinishLoop` 里被打包成 `VersionManifestAddendum("ModEntries")` 并
`ResourceLocator.ApplyAddendum(...)`，**在基础 manifest 之后应用** —— 这就是同名(类型,ID)条目能覆盖原版的原因。

`ModLoader.ResolvePath(path, rootPath)`：`if (!Path.IsPathRooted(path)) path = Path.Combine(rootPath, path); return Path.GetFullPath(path);`

### 5.2 于是有一条纯数据路线

```json
{ "Name": "MyPortraits", "Enabled": true,
  "Manifest": [
      { "Type": "Sprite", "Path": "portraits/Apex.png" },
      { "Type": "Sprite", "Path": "portraits/guiTxrPort_GenericMW_01_utr.png" }
  ] }
```

* ID = 文件名去扩展名 = `Apex` / `guiTxrPort_GenericMW_01_utr`，与原版同名 → 覆盖
* Path 被解析成 mod 目录下的绝对路径
* `VersionManifestEntry.FilePath = Path.Combine(Application.streamingAssetsPath, 绝对路径)`，
  .NET 的 `Path.Combine` 遇到已 rooted 的第二个参数会**直接返回第二个参数** → 得到 mod 目录里的绝对路径
* `IsResourcesAsset` 为 false、`IsAssetBundled` 为 false → 走 `SpriteFromDisk(FilePath)`
  → `File.ReadAllBytes` + `Texture2D.LoadImage` + `Sprite.Create` ✔

**但这条路线只对"有 `Description.Icon` 且没有 `PortraitSettings`"的驾驶员有效**，
也就是传奇佣兵 / 众筹者 / 剧情角色 / 新手组，覆盖不了随机雇佣兵和玩家指挥官。
所以最终工程选择了 System Mod + Harmony DLL。

### 5.3 System Mod 的入口约定

`systemMod.json` 需要 `DLL` + `DLLEntryPoint`（点号分隔的 `命名空间.类.方法`，默认方法名 `Init`）。
`AssemblyUtil.FindMethods(assembly, methodName, typeName)` 找到方法后：

1. 先按**参数名**注入：字典里有
   `modDir` / `modDirectory` / `directory`（都是 mod 目录），
   `modSettings` / `settings` / `settingsJson` / `settingsJSON` / `JSON` / `json`（都是 mod.json 的文本）
2. 失败再按**参数类型**尝试 `(string directory, string settingsJson)`

所以 `public static void Init(string modDir, string settingsJson)` 是标准写法。

Harmony 由 ModLoader 从
`BattleTech_Data\StreamingAssets\data\mods\HBS\0Harmony.dll`（**Harmony 1.x**，
用 `HarmonyInstance.Create` / `HarmonyInstance.Patch`，没有 `AccessTools.PropertyGetter`）加载。

## 7. 待办的增强方向

1. **在游戏里选图**：`PortraitSelectorElement.SetData(PortraitSettings)` + `SGPortraitCustomizationPopup.SetupOptions`
   是给脸谱列表生成条目的位置，可以往里面插"自定义图片"条目，做到游戏内点选而不必改 JSON。
2. **按尺寸预缩放**：目前一张 PNG 喂给所有 `PortraitSizes`；如需极致清晰，可按
   VERYSMALL/SMALL/MEDIUM/LARGE 生成 4 张缩放后的 Texture2D。
3. **场景内 3D 头模**：`BattleTech.Portraits.PortraitGen`（字段 `skinnedMesh`、`headMatList`、
   `brow/noseBridge/noseTip/chinTip/cheek/eyeScalar/jawScalar` 滑块）是角色创建"外貌"页里那个真模型，
   目前只是隐藏入口。要彻底替换需要在 `SGCharacterCreationNameAndAppearanceScreen` 上做 UI 手术。
4. **性别/年龄过滤**：图片池可以按 `PortraitSettings.get_Gender()` / `MatchesAge(age)` 分池。

## 8. `PortraitManager` 的三个清理函数会销毁贴图（0.1.0 失效的根因）

```csharp
// PortraitManager.Clear()
foreach (RenderedPortraitResult r in renderResults.Values)
    foreach (Texture2D tex in r.results.Values)
        if (Application.isPlaying) DestroyImmediate(tex);
renderResults.Clear();

// PortraitManager.ClearLargePortraits()
foreach (RenderedPortraitResult r in renderResults.Values) {
    DestroyImmediate(r[(PortraitSizes)512]);   // ← 顺带证明 LARGE == 512
    r.ClearSize((PortraitSizes)512);
}
Resources.UnloadUnusedAssets();                // ← 注意这一句

// PortraitManager.ClearPortraits(IEnumerable<PortraitSettings> settings)
foreach (PortraitSettings ps in settings) {
    RenderedPortraitResult r;
    if (renderResults.TryGetValue(ps.Description.Id, out r))
        foreach (Texture2D tex in r.results.Values) DestroyImmediate(tex);
    renderResults.Remove(ps.Description.Id);
}
```

由此得到三条必须遵守的规则：

1. **给游戏的贴图必须是"可以随时被销毁"的**。因此 0.2.0 把贴图分成两层：
   我们自己的 Prototype（永不交出）和交给游戏的 Handout（每个 `(settingsId, 尺寸)` 独占一张副本）。
2. **每次取用 Handout 之前必须验活**。Unity 对已销毁的 `UnityEngine.Object` 重载了 `==`，
   `tex != null` 会返回 false，这就是可靠的存活检测手段。
   （0.1.0 的 bug 正是"缓存返回死对象 → `texture == null` → 主动 return true → 退回 3D 渲染"，
   而且缓存中毒后不会自愈。）
3. **`Resources.UnloadUnusedAssets()` 不会销毁我们的 Prototype**，因为静态字典持有强托管引用。
   但这也意味着 Prototype 的内存是我们自己负责的 —— 所以按 64/128/256/512 四档缩放缓存，
   而不是留着 2048² 原图。

另外注意 `ClearPortraits` 只销毁**一部分** settings 的贴图：如果多个 settingsId 共用同一张贴图对象，
被销毁后其它条目的字典引用就变成死引用了（`ContainsSizes` 仍然为 true，UI 会读到死贴图 → 空白）。
这就是 Handout 必须"每个 settingsId 独占一张"的原因。

## 9. 性别从哪来

### 9.1 3D 形态：`PortraitSettings.get_Gender()` 是算出来的

```csharp
public Gender get_Gender() {
    if (headMesh <= 0.4f) return Gender.Male;        // (Gender)3
    if (headMesh >  0.6f) return Gender.Female;      // (Gender)2
    return Gender.NonBinary;                          // (Gender)4
}
```

`BattleTech.Gender` 的成员顺序（即数值）：

```
INVALID_UNSET = 0
None          = 1
Female        = 2
Male          = 3
NonBinary     = 4
```

这正是游戏自己在 `PilotGenerator.GetPortraitForGenderAndAge` 里筛选脸谱用的判据
（`ps.get_Gender() == gender`），所以 mod 用它做图片池的性别门控，与游戏语义完全一致。

### 9.2 固定位图形态：`HumanDescriptionDef.Gender`

就是 pilot JSON 里那个 `"Gender": "Male"` 字段，正常反序列化而来。
`Gender` 为 `INVALID_UNSET`（例如 `pilot_story_kamea.json`）或缺失时，mod 视为"未指定"，
回退到未标注性别的图片池。

### 9.3 于是"性别关联"不需要逐张配置

按目录名 / 文件名前缀自动推断：

* 目录段：`female|f|woman|women|girl|女` → Female；`male|m|man|men|boy|男` → Male；
  `nonbinary|non-binary|nb|enby|neutral|中性` → NonBinary
* 文件名前缀（`_` 之前）：同上

选图时先取"同性别"候选；为空则取"未标注"候选；再为空则用整个池子。
所以把图丢进 `portraits\male\`、`portraits\female\` 即可，几百张也不用逐张登记。

## 10. 编译器代码页的坑（日志乱码）

`csc.exe`（.NET Framework 4.x）在源码**没有 BOM** 时按系统 ANSI 代码页解码源文件。
中文 Windows 上是 GBK，于是 UTF-8 的中文字符串字面量被解成乱码后编进 DLL
（日志里出现 `鍚姩锛?` 这种典型的 UTF-8 被当 GBK 读的二次乱码）。

修法：编译时加 `/codepage:65001`；日志文件改为 UTF-8 **带 BOM** 写出，
这样在中文 Windows 上双击用记事本打开也不会乱码。

# 附录 2：0.3.0 的改造（安全启用/禁用/删除）

## 12. `LoadGameMod` 同样会加载 DLL（已用方法体字节直接确证）

用自写的 .NET 元数据读取器读 `Assembly-CSharp.dll` 的方法体，得到：

```
ModLoader::LoadSystemMod   static  IL=192   0x00ad callvirt -> get_DLL
                                            0x00b5 call     -> LoadAssemblyAndCallInit
ModLoader::LoadGameMod     static  IL=251   0x00b9 callvirt -> get_DLL
                                            0x00c1 call     -> LoadAssemblyAndCallInit
```

⇒ **Game Mod（`mod.json`）也能带 DLL。** 这与官方 Mod Support PDF §2.3.4 的说法一致
（"DLL … 对 Game Mod 是可选的，对 System Mod 是必需的"）。

## 13. 为什么"游戏 mod 禁用"不会崩（结构保证）

对比两条循环的"该 mod 被禁用"分支：

```csharp
// InitSystemModsLoop —— 崩
if (loadedSystemModStatus.ContainsKey(name)) {        // 0x00d2：校验的是【系统】表
    if (loadedSystemModStatus[name].enabled && def.Enabled) { LoadSystemMod(def); ... }
    else {
        Log("SystemModDef[" + name + "] is disabled. Skipping it.");   // 0x014b
        loadedGameModStatus[name].enabled = false;                     // 0x016b：写【游戏】表 → 缺键
    }
}

// InitGameModsLoop —— 安全
if (loadedGameModStatus.ContainsKey(name)) {          // 0x00d2：校验的是【游戏】表
    if (loadedGameModStatus[name].enabled && def.Enabled) { LoadGameMod(def); ... }
    else {
        Log("GameModDef[" + name + "] is disabled. Skipping it.");     // 0x0150
        loadedGameModStatus[name].enabled = false;                     // 0x016b：写自己那张表 → 键必然存在
    }
}
```

这个保证**与加载顺序无关**：游戏 mod 的禁用分支只在"刚校验过同一张表"之后才写它。

⇒ 把 `systemMod.json` 改成 `mod.json`，就从根上避开了那个 bug。

**改造注意事项**：
* `mod.json` 与 `systemMod.json` **绝不能同时存在**（同名会同时进两个状态表 → 又是重复键崩溃）
* 建议显式给 `"Manifest": []`，避免 `ExpandManifest` 对 null 列表做枚举
* 游戏 mod 的 DLL 在系统 mod 之后加载，但仍在进主菜单之前 —— 对 UI 补丁时间完全够

## 14. 让存档不再要求本 mod

`ModLoader.GetSaveAffectingModDefs()` 的签名（自写读取器直接读出）：

```
GetSaveAffectingModDefs   static=True public=True  IL=70  sig=00 00 15 12 79 01 0e
                                                                 └ GENERICINST, 1 个泛型参数
                                                                    15 12 <List`1> 01 0e(string)
```

即 **`public static List<string> GetSaveAffectingModDefs()`**。调用方：

* `GameInstanceSave..ctor`（存档时：决定这个存档"需要哪些 mod"）
* `GameInstanceSave.AreNecessaryModsInstalled`（读档时：算当前启用集合）

两边取值一致，所以在 Postfix 里把自己摘掉不会自相矛盾：

```csharp
// 只声明 ref __result，不声明 __instance —— 静态/实例方法都能匹配
static void GetSaveAffectingModDefs_Postfix(ref List<string> __result)
{
    if (__result == null) return;
    __result.RemoveAll(IsSelfName);
}
```

**必须放在 `enabled` 开关之前注册**：否则用户在配置里关掉头像替换后，产生的存档仍会被标记为"需要本 mod"。

`BaseModDef.IsSaveAffecting` 是 public 字段、构造函数里默认 `true`
（`BaseModDef..ctor` 偏移 `0x0035 ldc.i4.1 → 0x0036 stfld IsSaveAffecting`），
所以在 `mod.json` 里声明 `"IsSaveAffecting": false` 是第二道保险（能否反序列化未证实）。

**副作用**：补丁生效之前产生的存档（已记为必需）会反过来提示"缺少 mod"。
本项目接受这个代价（相关存档是测试档）。

## 15. 本次改造后的三种状态

| 操作 | 机制 | 结果 |
|---|---|---|
| 游戏内启用 | 正常加载 DLL + 打补丁 | 头像被替换 |
| 游戏内禁用 | `InitGameModsLoop` 的禁用分支（安全路径） | 头像恢复原版，状态文件不被污染 |
